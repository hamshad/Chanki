# Phase 7: Admin + Deck Pipeline
## Plan 07-01: Admin Gate & CRUD

**Goal**: Admin can author decks through a hidden gate and round-trip them as versioned JSON.

### Tasks
1. **Admin Gate (Easter Egg)**:
   - Update `App.tsx` header title `Chanki` to track click count (e.g., 7 fast clicks).
   - Once triggered, display a simple modal prompting for an access code.
   - If the code matches an env variable (e.g. `VITE_ADMIN_CODE`), grant access and route to `/admin`.
2. **Admin Dashboard (CRUD)**:
   - Create `AdminDashboard.tsx` view listing all local decks and a button to create new decks/cards.
   - Form inputs for all card fields: hanzi, pinyin, meaning, tone, tags (comma separated).
   - Use `db.cards` and `db.decks` to save locally. (Note: standard users never get writes synced to Firestore, but the admin needs this for local deck authoring).
3. **JSON Pipeline (Import/Export)**:
   - Add "Export to JSON" button that serializes the active deck and its cards to `DeckExportSchema`.
   - Add "Import from JSON" button that parses `DeckExportSchema`.
   - When importing, validate each card row with Zod schema. If any card fails, output a per-row error report rather than silently omitting it.
4. **Integration**:
   - Tie everything to a new route `/admin` (guarded by a simple state or context so direct navigation without the access code shows a 401/404).
